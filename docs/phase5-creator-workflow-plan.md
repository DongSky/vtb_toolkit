## 三、三个需求点差距分析

### ① 时间戳 —— 地基已有，链路断裂（完成度 ~40%）

**已有：**
- 实时 highlight 检测已接入弹幕泵（`src-tauri/src/commands/danmaku.rs:112`）：滚动 z-score 触发后 emit `highlight://alert` + 手机推送
- 离线复盘页有完整时间轴：密度曲线、点击跳转、拖选切片
- EDL 导出（`vtb-highlight/src/export.rs`）

**断裂点（逐条核实过代码）：**
1. **实时告警不落盘**：`HighlightAlert` 只 emit + 推送，全项目无 `markers.json`/`alerts.json` 写入 —— 下播即丢，切片时无法回看"直播时报过哪些高能点"
2. **前端无人监听**：`highlight://alert` 事件在前端零订阅（全部 `listen()` 调用中没有它），App 内连提示都没有，只有手机推送
3. **时间基准错位**：告警 offset 用的是弹幕泵启动时刻的 `started.elapsed()`，而非录制会话时间轴 —— 即使落盘也对不上录播文件
4. **无手动打点**：主播喊"这段要切！"或场控想标记时，没有任何入口（无快捷键、无 UI 按钮、无弹幕口令）
5. **复盘页时间轴只画密度曲线**，不显示 SC/舰长/开播等事件标记（requirements.md F 增补表中"直播事件时间轴"P1 未做），也没有标记点列表
6. **无时间戳清单导出**（`00:12:34 名场面` 文本格式，可直接贴 B 站评论/简介）

### ② 剪辑工具打通 —— 完成度 ~60%

**已有：** EDL（CMX3600）导出、拖选一键 `-c copy` 切片、双语字幕烧录、SRT/ASS 导出、弹幕 XML（可经 danmaku2ass 转弹幕轨）、内置预览播放器、biliup 投稿。

**缺口：**
1. **剪映（CapCut）草稿导出**——国内个人全职切片 man 的主力工具，EDL 根本导不进剪映；这是"打通"二字的最大缺口
2. **EDL 不携带标记点**，CMX3600 对 marker 支持极弱；缺 **FCPXML / Premiere XML**（marker + 片段都能带）
3. **无"素材包"一键导出**：切片 mp4 + 双语 SRT/ASS + 弹幕 ASS + 时间戳清单打包到一个目录、一键打开——目前分散在各按钮
4. 长录播（2–6h 原画）进剪辑软件卡顿，**无代理（proxy）低码率副本生成**

### ③ 封面设计 idea —— 完全未覆盖（完成度 0%）

全代码库仅 `RoomsPanel.tsx` 显示直播间封面（展示用，无关）。但**地基意外地好**：
- `multimodal.rs` 已有抽帧 + Anthropic 视觉打分 + AI 标题生成，管线已接线
- 场次报告已有弹幕 TOP/词云/SC 数据，transcript 全量落盘——封面文案所需的"直播内容理解"素材齐全

## 四、Phase 5 开发计划：创作者工作流打通

优先级依据访谈权重：时间戳（明确刚需）> 剪辑打通（"能打通会比较好"）> 封面 idea（"比较难说的"，探索性）。

### M5.1 直播打点系统（P0，先做）

- **时间基准统一**：打点/告警 offset 一律锚定录制会话时间轴（`meta.json` 的 session_start + part 偏移），未录制时锚定弹幕连接时刻并在 meta 标注基准来源
- **自动打点**：`HighlightAlert` 追加写入会话目录 `markers.jsonl`（type=auto，含 reason/z/danmaku_count）
- **手动打点**：三个入口——全局快捷键（tauri-plugin-global-shortcut）、弹幕面板按钮、弹幕口令（场控发特定弹幕触发，可配白名单 uid）
- **前端**：监听 `highlight://alert` 弹 toast；新增标记列表（可加备注、可删）
- **复盘页时间轴叠加**：markers + SC/舰长/开播事件竖线标记，点击跳转；离线 highlight 检测把 markers 作为强先验信号（人工点过的窗口加权）
- **导出**：时间戳清单文本（`HH:MM:SS 备注`，B站评论/简介格式）
- 验收：直播中按快捷键 3 次 + 触发 1 次自动告警 → 下播后复盘页时间轴显示 4 个标记且与画面对齐（±2s），导出清单可用
- e2e：`diag_markers`（注入合成弹幕峰值，校验 markers.jsonl 与录制时间轴对齐）

### M5.2 剪辑工具深度打通（P0/P1）

- **M5.2.1 剪映草稿导出（P0）**：生成 `draft_content.json` 工程目录——高能片段作为轨道片段、markers 作为标记、SRT 作为字幕轨。风险：格式无官方文档且随版本漂移，先做调研 spike 固定目标版本（以本机剪映专业版实测为准），失败则降级为"剪映可识别的 SRT+素材目录"方案
- **M5.2.2 FCPXML 导出（P1）**：带 marker + 片段，覆盖达芬奇/FCP/Premiere（均可导入 FCPXML 或经转换）
- **M5.2.3 素材包一键导出（P1）**：`导出素材包` = 切片 mp4 + 双语 ASS/SRT + 弹幕 ASS + 时间戳清单 + cover 候选帧，写入单目录并"打开所在文件夹"
- **M5.2.4 代理副本（P2）**：录完自动生成 720p 低码率 proxy（可开关），供剪辑软件流畅粗剪
- 验收：一场真实录播 → 剪映打开草稿能看到片段与字幕；素材包目录结构完整

### M5.3 封面设计辅助（P1/P2）

- **M5.3.1 候选帧抽取（P1）**：对 top-N highlight 窗口密集抽帧，复用 `AnthropicJudge` 视觉打分（表情张力/构图/清晰度/无转场花屏），输出 `cover/` 目录 top-K PNG
- **M5.3.2 封面创意生成（P1）**：LLM 输入 = 场次报告（弹幕 TOP/SC/词云）+ highlight 标题 + transcript 摘要 → 输出 3–5 组 {封面标题文案、副标题、构图建议、配色建议、适配平台（B站/YT 比例）}，写入 `cover/ideas.md`
- **M5.3.3 复盘页封面 Tab（P1）**：候选帧九宫格 + 创意卡片，一键复制文案/导出帧
- **M5.3.4 文生图草稿（P2，探索）**：可选接入图像生成 API 出概念草图；默认关
- 验收：离线管线跑完一场录播后 `cover/` 内 ≥6 张候选帧 + ideas.md；浅野实测反馈迭代 prompt

### 里程碑顺序与依赖

```
M5.1（打点+时间基准）──→ M5.2.1 剪映草稿（需要 markers）
                      └─→ M5.2.2 FCPXML / M5.2.3 素材包
M5.3 封面（独立，仅依赖既有 multimodal 管线，可并行）
```

### 工程原则（延续）

1. 每个功能配 vtb-e2e diag 工具，真实直播间验证（`diag_markers` / `diag_cover` / 剪映草稿以本机实测为准）
2. 产品路径与诊断路径共享实现
3. 时间基准是本阶段的横切关切：所有落盘事件（弹幕 JSONL、markers、字幕、告警）统一锚定 meta.json 会话时间轴，一次做对
4. M5.3 属探索性功能，先出最小可用版给浅野实测收集反馈，再决定投入深度

## 六、完成状态（2026-07-23）

三个里程碑全部实现并测试通过（Rust workspace + 前端 74 用例全绿）：

### M5.1 直播打点系统 ✅
- **时间基准**：markers.jsonl 存墙钟时间（与 danmaku.jsonl 同一套约定），读取时以 meta.json `started_at` 对齐——从机制上消灭了"弹幕泵启动时刻 ≠ 录制起点"的错位问题
- **自动打点**：实时告警（`danmaku.rs` 泵）在录制中时落盘 auto 标记 + emit `highlight://alert`（带 room_id）+ 手机推送
- **手动打点三入口**：弹幕面板按钮（可带备注）、全局快捷键 `Cmd/Ctrl+Shift+M`（tauri-plugin-global-shortcut，后台也可触发）、弹幕口令（房管发「打点 [备注]」，`打点歌吧` 之类的刷屏不误触发）
- **离线管线先验**：手动标记未被检出覆盖 → 自动补一个 ±15s 候选（带备注做标题）；已覆盖 → 加分。`timestamps.txt`（B站评论格式）在 AI 标题写回后生成
- **复盘页**：时间轴叠加打点（绿=手动/橙=自动）、SC（黄）、舰长（紫）、开播（灰）竖线；打点与事件列表点击跳转；导出时间戳清单按钮
- e2e：`diag_markers`（时间轴对齐 + 合并 + 清单格式全链路验证）

### M5.2 剪辑打通 ✅
- **FCPXML 导出**：整段录播 + 全部高能/打点作为帧对齐 marker（达芬奇/FCP 直接导入，Premiere 经转换）
- **剪映草稿导出（实验性）**：`draft_content.json` + `draft_meta_info.json`（对齐 pyJianYingDraft 文档化的 5.x 结构，微秒时间基），高能片段预切在视频轨；**未在真实剪映验证**，需本机实测后按版本微调
- **素材包一键导出**：`素材包/` = 切片 + 双语字幕 + danmaku.xml + timestamps.txt + cover 候选帧
- **代理副本**：一键 720p 低码率 proxy（粗剪流畅）
- 备注：弹幕 ASS 烧录轨（danmaku.xml→ASS 转换器）未做，暂靠 danmaku2ass 外部转换

### M5.3 封面辅助 ✅（按用户要求改用 gpt-image-2）
- **候选帧抽取**：top-N 高能片段密集抽帧（1280px JPEG）到 `cover/`
- **封面创意**：文本 LLM（复用全局 LLM 设置）→ 3-5 组 {标题文案/副标题/构图/配色/平台比例/image_prompt}，写 `cover/ideas.md`；上下文含高能标题、场次报告（弹幕数/营收/热词）、字幕节选、用户补充文本
- **gpt-image-2 生成**：Base URL / Key / 模型 / 尺寸全部手动可配（Key 仅会话内存不落盘）；勾选候选帧或任意本地图片作参考图（走 `images/edits` multipart），补充文本自动附加进 prompt；纯文生图走 `images/generations`；b64/url 两种响应都处理

- 备注：候选帧的视觉 AI 打分（M5.3.1 的可选项）未做——九宫格人眼挑选 + 参考图生成已覆盖主流程，打分属锦上添花
