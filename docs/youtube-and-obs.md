# YouTube 与 OBS 网页使用说明

YouTube 公开直播评论默认匿名读取，不需要 API Key、Cookie 或 Google 登录。底层使用固定版本的 YouTube.js 18.0.0；不提供 YouTube 评论发送、自动答谢或定时发言。原有 Bilibili 功能保留。

## 连接与录制

1. 在「弹幕」页输入 YouTube 直播链接、11 位视频 ID 或 `@频道`，点击「连接 YouTube」。也可在「房间」页收藏频道、查看直播状态并连接评论。
2. 在「录制」页设置输出目录和分段策略，再从房间卡片点击「监听录制」，或直接填写直播 URL 录制。频道入口每 30 秒检测开播；固定视频入口只对应该场直播。频道同时开播多个场次时选择列表中的第一场，需指定场次时使用视频 URL。
3. 录制依赖 FFmpeg、ffprobe 和最新版 yt-dlp。yt-dlp 可放在应用可执行文件旁，或加入 PATH；读取评论本身不需要安装 Node.js。YouTube 取流如要求 JavaScript 挑战运行时，请依照 yt-dlp 官方说明安装 Deno。受限、会员专属或需要登录的视频不保证匿名可用。
4. 录制开始后可在弹幕页选择录制会话打点，也可使用 `Ctrl+Shift+M`。预览断开不会停止录制所需的评论日志。结束录制会等待视频停止写入和文件整理。

录制目录包含视频分段、`recording.meta.json`、`danmaku.jsonl`、打点文件、兼容弹幕 XML。删除/撤回事件另存 `moderation.jsonl`；复盘读取时会过滤已撤回评论，原始采集日志保留。YouTube 房间、作者与消息使用原始字符串 ID，不与 B 站数值 ID 混用。

Super Chat、Super Sticker、会员、会员赠送/获赠保留平台文案和金额文本。明确币种的收入分别汇总；单独出现 `$`、`¥` 等无法确定币种时只保留原文，不并入人民币。YouTube 没有 B 站进房、点赞、粉丝牌的对应公开数据，因此不会合成这些事件。

## OBS 与独立网页

1. 先连接任意平台直播评论，再打开「OBS输出」，启动叠加层服务。默认端口固定为 **18990**，重启使用相同端口时 OBS 地址保持稳定。
2. 配置平台、直播筛选、主题、字号、宽度、行数、保留时间、头像和标识。筛选示例：`youtube:视频ID` 或 `bilibili:房间号`；留空表示所选平台的全部直播。
3. 点击「单独打开评论网页」即可独立显示。OBS 添加「浏览器」源，把生成的完整 URL 粘贴进去，建议评论尺寸 420×700，字幕 1920×200。
4. 同时展示两个平台可使用「全部平台」，也可以添加两个浏览器源，各自选择不同平台。修改显示配置后重新复制 URL 到 OBS。

正式网页背景透明。应用预览的棋盘格和连接提示仅用于预览，不会进入 OBS。页面支持重连、去重、删除、翻译更新。服务只监听本机；保持工具运行，并允许本机访问所选端口。`/api/status` 提供当前连接/录制状态。

## 字幕、复盘与投稿

「实时字幕」可输入 B 站房间号或 YouTube 来源，使用共同的本地 ASR/翻译管线，每个任务可单独停止。ASR 需要本地 Whisper 模型；翻译和 AI 分析需要用户配置的模型服务。离线处理、切片、工程导出与封面流程沿用现有界面。

YouTube 投稿使用 Google 官方桌面 OAuth 和分块续传，与匿名读取分开。在 Google Cloud 启用 YouTube Data API v3，创建桌面 OAuth 客户端后，到「账号」配置并由本人在浏览器授权；配置与刷新凭据保存到系统凭据库。在「复盘」选择切片填写标题等信息后上传，默认私享，支持进度与取消。未完成审核的 Google API 项目可能被限制为私享。当前没有用真实 Google 账号执行授权或上传验证。

## Windows 启动与构建

开发启动使用 `pwsh -File scripts/dev-windows.ps1`，它会同时管理前端开发服务器与桌面进程。直接运行普通 `cargo run` 生成的开发程序需要另行启动 `npm run dev`；正式打包程序内嵌网页资源，不需要 Vite 服务。

本机 Whisper 编译使用 Visual Studio 2022 与 LLVM/libclang 18。LLVM 22 配合当前 bindgen 会生成不兼容的 Whisper 绑定；不要通过跳过绑定生成来使用其他平台的结构布局。可将兼容库放入 `.tools/libclang18/clang/native`，或配置 `LIBCLANG_PATH`。检查：`pwsh -File scripts/check-windows.ps1`；打包：`pwsh -File scripts/build-windows.ps1`。

开发模式已排除 `target`、`.tools`、录制与模型目录的文件监听，避免大量生成文件拖慢前端加载。界面异常会显示错误信息和重新加载入口；评论滚动仅限列表区域。

Windows 模型默认保存到 `%LOCALAPPDATA%/vtb-toolkit/models`，避免安装目录无写入权限。录制监控通过文件句柄读取增长量，避免 Windows 缓存的目录大小导致误判断流；YouTube 首次取流允许 90 秒初始化，开始写入后保留 30 秒卡流检测与自动续录。网络重连期间仍可能缺失内容。

## 本机验证（2026-09-12 至 13）

- Windows 独立程序关闭 Vite 后正常启动，页面重载恢复 YouTube 评论与录制消费者。
- 真实 Bilibili 弹幕、YouTube 匿名评论、双平台 OBS 网页、筛选与自定义表情已验证。测试的是独立浏览器页与应用内预览，未操作 OBS 软件本身。
- YouTube 约 7 分钟录制会话自动续录出两段有效视频，H.264/AAC、亮度与音量检查通过，生成 MP4、评论日志、XML、打点和复盘统计。另一次 90 秒直接取流测试成功并正常停止。
- 复盘直接加载录制目录，内嵌播放器可播放 MP4，不必先运行离线分析。
- 通过界面下载 tiny 模型，使用本机合成语音运行真实 Whisper，得到 4 段英文字幕和 SRT。tiny 用于功能验证，实际直播建议选择更高质量模型。
- 前端 93 项测试通过；Rust 工作区 378 项通过，5 项外网/模型测试默认忽略。生产前端、Windows release 程序、NSIS 与 MSI 安装包构建成功。工作区严格 fmt/clippy 检查仍有原有格式和 lint 问题，`git diff --check` 通过。

本机直接运行 `target/release/vtb-toolkit.exe`，同目录已放置 yt-dlp；FFmpeg/ffprobe 使用本机 PATH。安装包不捆绑录制依赖，安装到其他目录后须按上文配置 yt-dlp、FFmpeg 与 ffprobe。

Google OAuth/真实投稿尚未验证，需本人配置并授权；AI 翻译、语义剪辑和封面生成的真实服务调用还需要配置模型服务。已完成对应的本地流程与自动化回归，不将其计为真实账号或真实模型服务验证。
